# Architecture and trust boundaries

`cli.py` loads task and policy configuration. `runner.py` owns Git snapshots, the repair loop, independent checks and artifacts. `codex.py` adapts the installed CLI. `advisors.py` adds optional read-only planning/review under shared budgets. `report.py` summarizes independent trials. `improve.py` versions task packs and enforces promotion gates. Python's standard library provides the core runtime.

`packs.py` handles deterministic discovery, inspection, task/repository suggestions and scaffolding. `optimize.py` orchestrates a single instruction proposal and paired holdout experiment, with aggregate accounting, a registry lock, holdout-consumption history and a durable audit. Proposal deltas preserve unrelated instructions; their empirical validation remains separate from deterministic application.

In the 0.5.4 development build, `session.py` opens native Codex for the default `sc`/`supercodex` path. Its private bootstrap includes the operator guidance, a catalog of bundled skill names/descriptions/absolute paths, selected pack context and optional command templates. The `skill-discovery` instructions guide the operator to check native session skills and the bundled catalog when a new task arrives, select a small relevant set, read its instructions and use native tools for research and coding. Already-read unchanged instructions can be reused. This selection remains model-guided rather than a forced dispatcher. The launcher inherits terminal handles, streaming, authentication and native permissions. `--native` is an explicit alias for this default.

There is no SuperCodex per-message hook or app-server hook preflight in the default launch path. `--no-prompt-hook` is a deprecated compatibility no-op. The earlier routing implementation is not registered by this launcher. Existing user hooks and global settings remain unchanged. The catalog does not install skills into the target checkout or turn their guidance into mandatory child-process execution. Native coding can edit and test directly; reported checks remain native evidence rather than a managed receipt.

`answer.py` is an explicit opt-in entry point that validates exact prompt and optional context input, then invokes the managed controller through buffered exec. It never opens another native operator. Time-sensitive answers have live web search available unless the policy explicitly restricts it; retrieved evidence and source links remain necessary. Research answers receive advisory receipts, while coding requests continue through implementation and independent checks. `SUPERCODEX_WORKER` prevents recursive answer calls. The outer native operator's inference remains outside child-run accounting; a receipt, not hook registration or a command listing, establishes execution.

`--managed` dispatches directly to `controller.py`, which owns the terminal prompt or single submitted request. `--task`, `--patch-only` and `--no-stream` also select this mode for compatibility and conflict with explicit `--native`; research-specific flags require managed mode. The controller makes a read-only preparation call in a disposable clone, validates the structured task, preserves pack acceptance requirements, and invokes `runner.py` directly. Explicit `--task` skips model preparation. Preparation usage and elapsed time reduce the remaining run budget; missing accounting stops further model stages. A receipt records actual execution, verification and application separately. Only a passing patch can be applied, after checking the source remains clean at its frozen commit and `git apply --check` succeeds. Managed failures do not fall back to native editing.

Explicit managed research/capability answers have advisory receipts and do not claim a verified coding result. Native research uses existing tools directly without requiring a repository snapshot or child process. This orchestration cannot prove that generated checks cover every requirement. Local setup/verifier commands are trusted code, not a hostile-code sandbox. After patch application, a later coding task requires a fresh clean committed source; the controller never commits or discards user work automatically.

For explicit managed requests with no committed target, preparation uses an empty Git workspace inside the private session. No target files are copied, and no repository is initialized in the user's selected directory. Research can proceed with available evidence and configured connections; coding is blocked with a request to select a clean committed `--repo` target. The receipt distinguishes this empty research context from a source snapshot.

`research.py` resolves preparation-only MCP presets and optional private user configuration. A named reference can import one existing Codex connection in memory with an explicit tool allow-list, without enabling blanket user configuration. Worker MCP selection remains separate; planning and review receive no research MCP configuration. Receipts record actual MCP server/tool/status events, while full events remain private. Local read-only permissions do not enforce remote MCP permissions, especially when a tool multiplexes read/write operations.

Managed CLI sessions use `app_server.py` for genuine message deltas, with `streaming.py` decoding only the preparation answer for display. `codex_home.py` supplies a private temporary home with access-only authentication; native user-home instructions, MCP configuration and hooks are not imported. Selected connections remain explicit. Keyring-only authentication and MCP OAuth stores are unsupported by this isolated live transport; the default native interface retains ordinary Codex authentication. The transport denies unsolicited approval requests, enforces a deadline and output cap, kills descendants, and converts the final cumulative usage snapshot into one accounted turn. Malformed or regressing usage leaves accounting unknown. The controller still validates the final structured result and independently verifies code. Partial text is provisional and cannot authorize patch application. `--managed --no-stream` selects the buffered `codex exec` path; transport errors never silently switch modes or retry a paid request.

The native launcher passes a short file-reading prompt and selected model/MCP overrides, keeping arbitrary task and pack text out of launch arguments. Existing native MCP connections remain available to the operator; managed child tools are selected separately. Native edits follow the relevant coding and verification skills. The operator reports the checks actually run; merely loading guidance does not establish verification or a managed result.

The core workflow is deterministic except model behavior and target commands. A run freezes a Git commit, clones it without sharing object storage, removes its remote, executes setup and baseline checks, then invokes Codex. Candidate patches include tracked modifications and new non-ignored files, compared to the frozen commit even if an agent creates a commit. Protected-path or changed-symlink violations fail the run.

Each verifier receives a fresh clone plus the candidate patch. It does not reuse ignored files, caches or processes from the worker. This catches accidental acceptance based on untracked/ignored helpers. Verifier commands come from the parent task definition. They are local host commands with a reduced environment, not a hardened remote grader. Test code can still be tricked through imported source, and a hostile process can attack resources available to the host user.

Managed model stages use a separate process session. The runner bounds output and kills the process group on timeout or completion, cleaning up descendants. Codex stdout/stderr is captured locally; valid JSON events are also extracted. Unknown event types are retained. Missing usage prevents further model stages after a failed attempt. A successful patch with missing usage can be returned, but its cost remains unknown and cannot satisfy a dollar-based promotion gate.

Artifacts include the task and policy, base commit, platform/runtime information, pack/task/context/MCP hashes, baseline output, phase prompts/events, candidate patches, verification output, optional plan, and the result JSON. MCP values are not serialized into results, only names and a hash; do not put literal secrets in any configuration.

The CLI parser is also the source of the `commands` inventory. The `skills` command exposes bundled names, descriptions and paths, or reads the selected skill, without a model call. `skills --search` performs deterministic keyword matching over bundled names and descriptions; it does not search third-party skills or decide whether an instruction is appropriate. The operator separately considers skills advertised by the native session and reads chosen files before applying them. `agent_tools.py` renders the operator skill and a compact worker inventory using an absolute `launch.py` entry point. The Codex adapter saves its effective prefixed prompt and passes a cooperative worker marker to child processes. CLI dispatch blocks new jobs/mutations under this marker so ordinary nested use cannot silently escape accounting. Discovery-context hashes participate in comparison and routing provenance. See [operator and worker behavior](AGENT_USAGE.md).

Output inside the source repository must be explicitly Git-ignored; otherwise the runner rejects it before writing. Promotion requires matching tools, CLI/platform/Python metadata and unique trial IDs, and refuses to replace an active release unrelated to the candidate's original baseline. The optimizer adds provenance, distinct-prompt and fresh-holdout checks. These checks do not provide hostile-code isolation or statistical proof.

## Extending the adapter

`run(policy, model, workspace, prompt, mcp, timeout, log)` returns completion status, return code, failure reason, message, events, usage and estimated cost. `advise(..., role, mcp=None)` adds read-only preparation, planning and review, with structured schemas for preparation and review. Its optional MCP argument is accepted only for preparation. Keep result usage normalized as `input_tokens`, `cached_input_tokens`, `output_tokens`. Preserve unknown usage and prices as `None`. New backends must demonstrate timeout cleanup, structured response behavior and accounting with contract tests before claiming support.

## Experimental layer

`experimental/` adds separate opt-in commands. `parallel.py` runs isolated candidates or read-only specialists; `routing.py` fits a local classifier from matched outcomes; `memory.py` retrieves verified experience. `ace.py` maintains structured playbooks, while `gepa.py` integrates the optional upstream optimizer. `recursive.py` provides typed nested read/search/delegate calls. `finetune.py` exports verified patch datasets and optionally invokes TRL/PEFT training. These workflows keep ordinary coding acceptance in `runner.py` and pack promotion in `improve.py`.

Retrieved advice is bounded, marked untrusted and fingerprinted in run records. Paired promotion trials must use matching external advice. Instruction candidates retain cumulative development-task and normalized-prompt provenance across copies and releases. Matching hashes catch exact overlaps; semantic contamination remains a dataset-curation problem. See [experiment contracts and limits](EXPERIMENTS.md).

## Deliberate boundaries

The managed controller can apply a verified patch locally; `--patch-only` and the lower-level `run` command leave application to the user. The project does not commit user project changes, publish PRs, update tickets, alter global Codex configuration, grant trust to unrelated hooks or schedule itself. The default launcher grants no SuperCodex hook trust. The native operator retains Codex's existing capabilities and permissions; skill instructions guide their use rather than restricting them mechanically. The empty research workspace receives its own disposable initialization commit. The optional training command can update an open-weight model through a local LoRA adapter; hosted Codex weights are unchanged. There is no container sandbox, embedding index, automatic parallel-worker merge system or resumable long-running workflow scheduler. The learned router and lexical retrieval are experiments requiring representative data and evaluation.
