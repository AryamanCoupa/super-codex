# Research and practice coverage

Audited against the version 0.3 implementation on 2026-11-05. This inventory covers the sources reviewed in [the original research](RESEARCH.md), [the extension](RESEARCH_UPDATE.md), and [the experimental implementation guides](EXPERIMENTS.md). Reading depth and source limitations remain documented in those reviews. It is not an exhaustive survey of published research, a reproduced benchmark, or evidence that enabling every technique improves results.

**Standard default** means part of ordinary task execution or its normal integrity checks. **Standard option** requires a policy, pack or command choice. **Experimental** means executable functionality behind the explicit `experimental` CLI. **Optional upstream** means an actual external implementation is invoked after installing its extra. **Not implemented** means the source informed a decision, but its algorithm/tooling is absent. An implementation described as **adapted** differs materially from the cited method.

## The requested experimental capabilities

| Capability | Availability and entry point | Implementation and fidelity | Verification boundary |
|---|---|---|---|
| Parallel cheap-worker teams | Experimental: `teams` | [Read-only specialist clones](../codex_harness/experimental/parallel.py), optional stronger synthesis, then one verified implementer | Exercises decomposition and coordination. It does not concurrently edit or merge worker patches. |
| Best-of-N selection | Experimental: `best-of-n` | Independent runner trials; select only an externally passing patch by measured candidate cost or explicit token proxy | All candidate spending counts. Identical answers or majority agreement are not acceptance criteria. |
| Learned model routing | Experimental: `router train`, `run --router` | [Fitted TF-IDF/logistic classifier](../codex_harness/experimental/routing.py) from matched outcomes and costs, with validation, context checks and stronger-model fallback | Genuine fitted weights; an adapted router, not RouteLLM's published preference-trained architecture. Scores are uncalibrated. |
| Successful-experience retrieval | Experimental: `memory build`, `run --memory` | [BM25 index](../codex_harness/experimental/memory.py) of compact verified trajectories and provenance | Lexical retrieval, not a dense vector index. Current-task/holdout and stale-context filters reduce known contamination; semantic leakage still needs review. |
| ACE context adaptation | Experimental: `ace`, `run --ace-playbook` | [Local structured playbook variant](../codex_harness/experimental/ace.py): generator evidence, separate reflector/curator calls, stable bullets, feedback counters, incremental updates, deduplication, pruning and retrieval | Lexical matching replaces the paper's semantic machinery. Helpfulness votes are model attributions, not causal measurements. No exact ACE benchmark reproduction. |
| GEPA optimization | Optional upstream: `gepa` with `.[gepa]` | [Adapter](../codex_harness/experimental/gepa.py) calls real `gepa.optimize`, pinned to 0.1.4, using upstream Pareto selection, reflective mutation and merge proposals | Actual upstream search engine. An offline integration test exercises it when installed; published GEPA scores and live Codex gains are not reproduced. |
| Recursive model calls | Experimental: `recursive` | [Bounded read/search/delegate/answer environment](../codex_harness/experimental/recursive.py), root/child model selection, global call/depth limits and final verification | An adapted recursive-call workflow. It does not execute model-generated REPL programs as in the exact RLM method. Wrapper retrieval caps do not restrict Codex's native read tools. |
| Distillation and model fine-tuning | Experimental export; optional upstream training: `finetune export`, `finetune train` with `.[finetune]` | [Verified patch dataset export and genuine TRL/PEFT LoRA SFT calls](../codex_harness/experimental/finetune.py), completion-only loss, local adapter output | Training wrapper tests use injected dependencies. No real GPU/MPS/CPU training job or downstream model-quality gain has been validated. Hosted Codex weights are not changed. |

These experiments produce auditable artifacts. They do not silently replace ordinary execution. See [commands and configuration](EXPERIMENTS.md), [parallel workflows](EXPERIMENTAL_PARALLEL.md), [routing/retrieval](EXPERIMENTAL_ROUTING.md), and [ACE/GEPA](EXPERIMENTAL_OPTIMIZERS.md).

## Best-practice controls and their limits

| Practice | Where it is enforced or supported | Limit |
|---|---|---|
| Define executable acceptance criteria | Task loading rejects empty checks; scaffolded packs leave unknown checks incomplete | A passing command can still have inadequate assertions. |
| Separate implementation from verification | Disposable worker and verifier clones; protected-path checks | Trusted local commands run on the host. Clones are not a hostile-code container boundary. |
| Keep model/tool context relevant | Selected pack skills/MCP tools, bounded feedback and experimental advice | Native Codex/managed environment context is outside complete wrapper control. |
| Preserve useful learned guidance | Deterministic bounded edits; incremental ACE operations; self-contained release skills | New advice can still be wrong; usefulness counters do not prove causal benefit. |
| Prevent known evaluation contamination | Exact/normalized task identities, source provenance, grouped routing data, memory exclusions, historical ACE/GEPA development identities | Semantic overlap, accessible holdout files and memorized benchmark answers still need dataset curation. |
| Use fresh promotion evidence | Standard `pack optimize` reserves consumed holdouts and enforces diversity | Manual experiments and experimental candidate generators do not maintain that registry history automatically. |
| Match comparison conditions | Promotion/runtime/tool/policy metadata; router matched-trial checks | Different hardware load and provider nondeterminism can still affect outcomes. |
| Account for all extra computation | Candidate, analyst, coordinator, recursive, reflection and rollout spending; known/unknown fields | Token proxies are not dollars. Local training hardware cost remains unknown. Include historical data collection when estimating payback. |
| Bound experimental work | Candidate/concurrency/depth/call limits and shared usage budgets; subprocess timeouts | Usage limits are soft between stages. Parallel batches and individual training steps can overshoot. |
| Fail visibly when accounting or infrastructure breaks | Experimental stop statuses, retained logs, promotion exclusion of infrastructure outcomes | Completed artifacts may remain inspectable; an incomplete experiment is not an approved improvement. |
| Version, inspect and roll back | Pack registry with immutable-by-tool releases and active/previous pointers | Manual filesystem edits are outside that guarantee. Training outputs never automatically replace the active policy. |
| Evaluate components independently | Repeated suites and documented cheap/strong/standard/experimental ablations | Offline orchestration tests and one earlier live smoke do not establish general accuracy or savings. |

Seven focused skills are bundled: `debug-with-evidence`, `browser-verify`, `github-context`, `atlassian-context`, `evaluate-harness`, `select-experiment`, and `curate-learning-data`. Packs load the skills explicitly selected in their manifests. These skills guide decisions; deterministic validation remains in code. They are not a catalog of every possible engineering practice or an automatic global installation.

Version 0.3.1 additionally provides a separately installable `super-codex` operator skill and automatic compact command awareness for managed workers. The parser supplies the current inventory, and detailed command help loads on demand. [Agent usage](AGENT_USAGE.md) covers cross-project installation, path handling and the distinction between top-level orchestration and already-budgeted workers.

Version 0.5 added enforced entry-point orchestration. In 0.5.6, default `sc` uses the native Codex UI with a lightweight per-message skill reminder: select relevant guidance, read it and complete the task using current tools. The reminder supplies a bounded keyword shortlist and discovery/verification entry points without a model call or saved prompt copy. Skill choice remains model-guided; hook delivery alone does not prove application or improved accuracy. Managed workflows remain explicit: `answer`, `sc --managed` or `sc --prompt-hook answer` prepare coding tasks, validate contracts, invoke the verified runner and produce receipts. Preparation spending counts toward that job's budget; the outer native operator is accounted separately. Source/base checks gate patch application. All managed roles receive the twelve-skill catalog and role-bounded guidance; `skills --search` matches bundled metadata without model calls. `sc --no-prompt-hook` keeps bootstrap skills without a per-message reminder. Neither skill availability nor a receipt proves every optional technique was appropriate. Generated acceptance checks still need meaningful assertions.

Version 0.5.1 lets research preparation use an empty private workspace when the selected directory has no committed Git snapshot, and introduces separately selected research MCP connections. It records actual tool calls without claiming that advisory answers passed coding checks. Remote permissions still depend on server controls and credentials; tool-name filtering cannot restrict operations hidden inside a multiplexed tool.

The remaining absent algorithms are explicit in this map. The meaningful next claim comes from a representative, reproducible held-out comparison, with independent correctness review and all optimization costs included. [Validation status](VALIDATION.md) records what has actually been executed.
