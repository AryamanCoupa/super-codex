---
name: skill-discovery
description: Find and select relevant skills for a task from the native session and bundled SuperCodex catalogs, read their instructions and apply only the guidance that helps complete the request.
---

At a materially new task, identify the requested outcome and inspect the names and descriptions advertised to the current role by the session or SuperCodex catalog. A per-turn skills hook may supply up to three keyword matches; treat them as candidates and consider other available skills when the shortlist misses the task. Honor skills explicitly named by the user and higher-priority rules for their use. Choose the smallest relevant set based on stated scope, not a keyword alone. This skill is the selection procedure itself: do not select or reread it recursively. Default skill reminders require reading and applying guidance in this session, not a child `answer` command or managed receipt. Respect those requirements only when explicit answer routing is active. Managed workers apply skills to their assignment without invoking `answer` or another model job.

When the choice remains unclear, use the exact absolute Python/launcher pair printed in the operator or session bootstrap, followed by `skills --search "short task keywords"`. Use a few task terms such as `github repositories`, `browser verification` or `debug failing tests`. The command matches keywords against bundled skill names and descriptions only. It is not semantic retrieval, an internet search or a search of third-party skills. A no-match result means this bundled search found no match; inspect the already-advertised native catalog separately and continue with ordinary tools when no relevant skill is available. Do not invent a skill or its capabilities.

Read each selected `SKILL.md` at its advertised absolute path, or use the advertised provider's read tool for a non-filesystem skill. For a bundled skill, the same absolute launcher with `skills NAME` prints its instructions. Expand only documented path aliases. Read linked resources when the skill requires them for the current task. Reuse unchanged instructions already read in this session; do not load all skill bodies, scan unrelated directories or guess installation paths.

If the task needs an integration or skill outside the available catalogs, use the environment's advertised skill/plugin discovery tools when appropriate, following their instructions and the user's scope. Discovery does not authorize downloads, installation, account connections or unrelated external writes. Do not install a matching search result automatically or start an extra model process just to select a skill. Report a genuinely missing capability when it blocks the request, without treating an optional skill as a prerequisite for work that native tools can perform.

Briefly name the selected skills when first applying them, for example, "I'll use research-with-sources and github-context for this lookup." Then follow their relevant instructions and complete the actual task using current tools. For a defect, apply `debug-with-evidence` to investigate and verify a repair. For useful independent subtasks, read `economical-delegation`, decide whether multi-agent work adds value, and delegate bounded work when appropriate. Do not claim a skill was used merely because its name appeared in search results; distinguish discovered, read and applied guidance, and report concrete output or verification evidence. Loading a skill is preparation, not a completed result or managed-run receipt.

Reconsider the selection when the goal, task type or required tools materially change, or when new evidence exposes a relevant gap. Keep already useful guidance and the user's existing constraints. Routine follow-ups do not require repeated searches, announcements or file reads. This skill selects guidance within the current workflow; it neither installs routing hooks nor changes the selected session mode, permissions or worker budget.
